# Эксперимент по генерации pandas кода для WikiTableQuestions

## Контекст
Мы использовали **Qwen Coder (next)** для генерации кода на pandas по задаче **WikiTableQuestions**. Модель получала на вход:
- сериализованную таблицу,
- названия колонок,
- вопрос.

Цель модели — сгенерировать код, который возвращает правильный ответ.

## Схема генераций (три этапа)

### 1. Первая генерация (прямая)
Модель генерирует код на основе исходных данных (таблица + вопрос).

### 2. Вторая генерация (коррекция синтаксиса)
- **Условие:** код из первой генерации упал с ошибкой.
- **Вход модели:** исходные данные + сгенерированный код + текст ошибки.
- **Параметры:** 4 попытки с повышением температуры на 0.23 начиная с 0.3.
- **Задача:** исправить **синтаксическую ошибку**.

### 3. Третья генерация (логическая коррекция)
- **Условие:** код из первой генерации был синтаксически верным, но давал неверный результат.
- **Вход модели:** исходные данные + сгенерированный код (из первого или второго этапа).
- **Параметры:** 4 попытки с повышением температуры на 0.23 начиная с 0.3.
- **Задача:** исправить **логическую ошибку** (не меняя синтаксис).

## Технические детали

### Структура эксперимента
Эксперимент проводился в два этапа. На каждом этапе применялась трёхступенчатая схема генерации и исправления кода.

### Сериализация таблиц
Для преобразования таблиц во входной формат модели использовалась сериализация **Tapex**:
- Формат: `col : колонка1 | колонка2 | ...`
- Каждая строка: `row N : значение1 | значение2 | ...`
- Таблица строится как линейная строка с заголовком и всеми строками

### Нормализация и сравнение
- Для корректного сравнения ответа с эталоном модель должна применять функцию `convert_type` из [semtab_serializer](https://github.com/YRL-AIDA/semtab_serializer/blob/Refactor_WTQ/utils/normalize.py)
- Для сравнения строковых данных предусмотрена функция `find_word` (на данный момент — заглушка)

**Принцип работы нормализации:**  
Исходные данные во всех колонках таблицы изначально представлены в виде строк. Для их корректного сравнения и обработки применяется автоматическое определение типов с помощью регулярных выражений. Функция `convert_type` анализирует значение и пытается привести его к одному из следующих типов: `bool`, `int`, `float`, `date`, `datetime`, `time`. В случае успеха возвращается преобразованное значение, иначе — исходная строка (или `pd.NA` при соответствующем флаге). Такой подход позволяет единообразно обрабатывать числа в разных форматах (с пробелами, валютами, процентами, разделителями тысяч, скобками) и даты в различных стандартах (ISO, европейском, американском, с названиями месяцев).

### SQL-запросы (второй этап)
- Использован датасет **Squall** (11 276 запросов для WTQ): [https://github.com/tzshi/squall](https://github.com/tzshi/squall)
- SQL-запрос передавался модели как дополнительный контекст

### Промпты
Промпты для каждой итерации генерации доступны в конфигурационном файле:  
[https://github.com/YRL-AIDA/semtab_serializer/blob/Refactor_WTQ/WTQ/Qwen/config.py](https://github.com/YRL-AIDA/semtab_serializer/blob/Refactor_WTQ/WTQ/Qwen/config.py)  

Пример базового промпта для первой итерации (прямая генерация):
You are a Python expert specializing in pandas. You are given a question and a table.
Your task is to translate the given natural language question into a single-line pandas expression...
Always use convert_type('...') for numeric and date constants from the question...
Always use find_word(value: str)-> str when filtering by string entities mentioned in the question...

Полные версии промптов для синтаксической и логической коррекции также находятся в указанном файле.
